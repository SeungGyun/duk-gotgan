# 목표

곳간에 쌓인 강의 노트를 내 티스토리 블로그(`ilovehsk.tistory.com`)에 올립니다.
곳간은 집 안에서만 열리는 화면이라, 밖에서 읽으려면 블로그로 나가야 합니다.

**곳간과 블로그는 다른 것을 담습니다.** 곳간은 걸러 낸 것까지 전부 쌓아 두고
화면이 골라 보여주는 곳이고, 블로그는 **읽을 만한 것만** 나가는 곳입니다.
그래서 곳간에 있다고 다 올리지 않습니다.

---

# 무엇을 올리는가

## 대상

`lectures` 중에서 아래를 모두 만족하는 것.

| 조건 | 값 | 왜 |
|---|---|---|
| `is_hidden = 0` | 현재 버전만 | 재요약으로 밀려난 옛 버전은 올리지 않습니다 |
| `verdict IN ('expert', 'practical')` | 399편 | 아래 참고 |
| 주인이 제외하지 않은 것 | `user_lectures.excluded_at IS NULL` | 자기 곳간에서 뺀 것을 자기 블로그에 올릴 이유가 없습니다 |
| 아직 안 올린 것 | `blog_posts` 에 없음 | |

**왜 판정 두 종류인가.** 공개 강의 1,126편의 판정 분포가 이렇습니다.

```
expert         167
practical      232   ← 여기까지 올립니다 (399편)
introductory   368
irrelevant     272
promotional     87
```

`irrelevant` 와 `promotional` 은 곳간이 "이건 강의가 아니다"라고 판정한
것들입니다. 그것까지 올리면 블로그가 자동 생성물 1,126개로 덮이고,
기존 글 167개가 그 안에 묻힙니다. `introductory` 는 판단이 갈려 일단 뺐습니다 —
나중에 `BLOG_VERDICTS` 한 줄로 넣을 수 있습니다.

## 순서

`expert_score` 내림차순, 같으면 최근 것 먼저. **전문성 높은 것이 먼저 나갑니다.**

한 번에 한 편만 집습니다. 뒤에서 점수가 더 높은 새 강의가 들어오면 그것이
다음 차례가 됩니다 — 목록을 미리 확정해 두지 않는 이유입니다.

# 문서 처리

## 제목

곳간 제목(= 유튜브 영상 제목)은 **쓰지 않습니다.** `[일본경제상황] "엔화 폭락에
미국까지 나섰는데.." 다카이치는 도대체 무슨 생각일까...` 같은 것이라, 그대로
올리면 블로그가 유튜브 썸네일 문구로 채워집니다.

**요약을 읽고 새로 만듭니다.** 공백 포함 30자 이내.

- `one_liner` 는 그대로 못 씁니다 — 평균 32자, 최대 52자로 45%만 조건을 만족합니다.
- 그래서 `agy` CLI 를 한 번 부릅니다. 자막이 아니라 **이미 만들어진 요약**만
  넘기므로 입력이 작습니다(수천 토큰).
- **못 부르면 그냥 자릅니다.** agy 가 없거나 실패하면 `one_liner` 를 어절
  경계에서 30자로 자릅니다. 제목 하나 때문에 발행 자체가 멈추면 안 됩니다.

## 본문

### 빼는 것

- **시간 표시.** `sections[].startSec` 은 애초에 그리지 않고, 본문 글자 안에
  섞인 `[51:53]` `[1:24]` 같은 마커는 정규식으로 지웁니다. 실측에서 요약
  400편 중 11편이 불릿 앞에 `[MM:SS]` 를 달고 있었습니다.
- **링크.** `https?://…` 와 `youtu.be/…` 를 지웁니다.
- **판정 근거.** 점수·루브릭·red_flags 는 곳간 안에서 쓰는 값입니다.

`[MM:SS]` 만 지우고 `9:30` 같은 것은 남깁니다 — 시계 시각과 구별할 방법이
없어서, 지우려다 "오전 9:30 회의" 같은 멀쩡한 문장을 부숩니다.

### 담는 것

```markdown
{one_liner}

**이런 분께** {target_audience}
**알고 있으면 좋은 것** {prerequisites 를 · 로 이음}

## {sections[0].title}

- {bullet}
- {bullet}

## {sections[1].title}
…

{closing}

---

> 출처: {channel_title} 채널
```

`sections` 가 비어 있는 옛 형식(시드 데이터)은 올리지 않습니다.

### 출처

**남기지 않습니다.** 처음 두 편(#191·#192)에는 `> 출처: {채널명} 채널` 한 줄을
붙였는데, 블로그 주인이 자기 글로 두기로 정해 뺐습니다 (2026-08-08). 유튜브
링크를 빼기로 한 것과 같은 결정의 연장입니다. 이미 올라간 두 편도 같이
고쳤습니다.

## 태그

`lectures.tags` 를 그대로 씁니다. 요약 스키마가 3~8개를 **필수**로 받고 있어서
이미 전부 채워져 있습니다 (`llm/schemas.py` 의 `LectureSummary.tags`).
따로 만들 것이 없습니다.

## 카테고리

**곳간 키워드 = 블로그 최상위 카테고리.** 없으면 `--create-category` 로 만듭니다.

- 영상 하나에 키워드가 둘인 경우가 2,317건 중 50건 있습니다. **먼저 데려온
  키워드**를 씁니다 (`video_keywords.discovered_at` 오름차순) — 안 그러면
  같은 영상이 실행할 때마다 다른 카테고리로 갈 수 있습니다.
- 채널 구독 키워드(`@gaingetv`)는 핸들 대신 `channel_title` 을 씁니다.
  `@` 로 시작하는 카테고리는 메뉴에서 읽히지 않습니다.
- 이름에 `/` 가 들어가면 `-` 로 바꿉니다 — 티스토리에서 `/` 는 부모/자식
  구분자라, 그대로 두면 엉뚱한 곳에 하위 카테고리가 생깁니다.
- `archived` 된 키워드도 그대로 씁니다. 곳간에서 지웠어도 그 강의가 어디서
  왔는지는 바뀌지 않습니다.

**주의 — 카테고리 명령은 트리 전체를 다시 저장합니다.** 티스토리에 개별 추가
API 가 없습니다. 새 카테고리가 만들어지는 동안 브라우저 관리 화면에서
카테고리를 편집 중이면 한쪽이 덮입니다. 처음 며칠은 관리 화면을 닫아 두는
편이 안전합니다.

기존 블로그에는 최상위 9개(`웹프로그램`, `DB&NoSql`, `OS` …)가 있고
`주식` 은 이미 있어 재사용됩니다. 나머지 키워드는 새로 생깁니다.

**첫 발행에서 확인했습니다** (2026-08-07, 글 #191). 새 카테고리 `경제` 가
맨 뒤에 붙고 기존 40개 항목은 이름·번호·글 수까지 그대로였습니다 —
트리를 통째로 다시 쓰지만 잃는 것은 없습니다.

# 스케줄

**별도 잡입니다.** 워커에 `publish` 를 하나 더 붙입니다 — 검색·자막·요약과
락이 다르므로 서로를 기다리지 않습니다.

```
1분마다 깨어남
  └ 지금이 다음 차례인가? (app_state 의 blog.next_at)
      ├ 아니오 → 끝
      └ 예 → 한 편 올리고, 다음 차례를 2~10분 뒤 랜덤으로 적어 둠
```

**다음 시각을 DB 에 적어 둡니다.** 메모리에 두면 워커를 재시작할 때마다
초기화돼서 쿨링이 없던 일이 됩니다 — 자막 냉각이 정확히 그래서 깨져 있었습니다
(`app/db/state.py`). 재시작해도 적어 둔 시각이 그대로라 간격이 지켜집니다.

2~10분이면 평균 6분, 하루 240편입니다. 처음엔 5~20분(하루 115편)으로
잡았다가 줄였습니다 — 그때 기준으로는 399편을 다 내보내는 데 3.5일이
걸렸는데, 지금은 이틀이 안 걸립니다.

# 실패를 다루는 법

| 무엇 | 어떻게 | 왜 |
|---|---|---|
| 세션 만료 (`whoami` exit 2) | `tistory login --headless` 로 먼저 되살려 봅니다 | 대개 사람이 필요 없습니다 — 아래를 보세요 |
| 되살리기 실패 | 2시간 뒤로 미루고, 로그와 화면에 `tistory login` 안내 | 여기까지 왔으면 캡차·기기인증처럼 정말 사람이 해야 하는 단계입니다 |
| `whoami` 가 그 밖의 이유로 실패 | 10분 뒤로 미룹니다. **세션 만료로 적지 않습니다** | 네트워크가 한 번 튄 것일 수 있습니다. 8/9 00:01 이 그랬는데, 만료로 세어 두 시간을 자고 02:01 에 아무 일 없이 이어졌습니다 |
| `tistory` 없음 | 잡을 건너뜀 | |
| 발행 실패 | 3회까지 재시도, 넘으면 그 강의는 영구 제외 | 한 편이 막혀 뒤가 통째로 밀리면 안 됩니다 |
| 제목 생성 실패 | 잘라 쓰고 계속 | 발행을 멈출 이유가 아닙니다 |

**죽은 세션은 대개 스스로 되살립니다.** 티스토리 세션 쿠키(`TSSESSION`)는
만료시각이 없는 세션 쿠키라 서버가 사나흘이면 끊는데, 같이 저장된 카카오 SSO
쿠키(`_kau` 1년, `_kaslt` 한 달)는 그때도 멀쩡합니다 — 창 없는 로그인 한 번이면
살아 있는 카카오 세션이 새 티스토리 세션을 받아 옵니다(실측 5.5초, 비밀번호도
사람도 필요 없음). 이것이 없던 8월 13일에는 하루가 통째로 날아갔습니다: 두
시간마다 열두 번 확인하고 열두 번 다 "사람이 로그인해 주세요"만 적은 채 0편.

**중복 발행을 구조로 막습니다.** 올리기 **전에** `blog_posts` 에 행을 만들고
(`PENDING`) 그다음 CLI 를 부릅니다. CLI 가 글을 만들었는데 우리가 결과를
못 받는 경우가 있을 수 있어서, 재시도 전에는 같은 제목의 글이 이미 있는지
`tistory post list --keyword` 로 확인하고 있으면 그것을 우리 것으로 받아 적습니다.
**제목은 첫 시도 때 정해 행에 적어 둡니다** — 매번 새로 만들면 재시도 때 제목이
달라져 이 확인이 소용없어집니다.

# 켜는 법

**기본은 꺼져 있습니다.** `.env` 에 한 줄을 넣어야 돕니다.

```
BLOG_ENABLED=true
```

공개 발행은 되돌리기 번거롭습니다(올라간 글을 하나씩 내려야 합니다).
워커를 재시작했다는 이유만으로 남의 블로그에 글이 나가서는 안 되므로,
켜는 것은 사람이 한 번 명시적으로 합니다.

| 설정 | 기본값 | |
|---|---|---|
| `BLOG_ENABLED` | `false` | 켜는 스위치 |
| `BLOG_VISIBILITY` | `public` | `--publish -y` 로 바로 공개 발행 |
| `BLOG_VERDICTS` | `expert,practical` | |
| `BLOG_MIN_INTERVAL_MIN` / `BLOG_MAX_INTERVAL_MIN` | `2` / `10` | |
| `TISTORY_BIN` | `tistory` | |
| `TISTORY_BLOG` | (비움) | CLI 기본 블로그를 씁니다 |

첫 며칠은 `BLOG_VISIBILITY=private` 로 두고 몇 편 확인한 뒤 `public` 으로
바꾸는 것도 됩니다. 이미 올라간 글은 `tistory post visibility <id> public` 으로
따로 바꿉니다.

발행 이력이 사라져도 곳간은 그대로 돌아야 합니다.

# 정하지 않은 것

- **화면.** 지금은 실행 로그(`crawl_runs`, `job='publish'`)에 한 줄씩 남는 것이
  전부입니다. 곳간 화면에서 "이 강의는 블로그에 올라갔다"를 보여줄지는 나중에.
- **수정 반영.** 재요약으로 요약이 바뀌어도 이미 올린 글은 그대로 둡니다.
  `tistory post edit` 로 덮는 것은 나중에.
- **`introductory` 368편.** 넣을지 말지는 몇십 편 올라간 것을 보고 정합니다.
