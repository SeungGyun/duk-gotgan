# 덕!곳간 웹 UI

React + Vite + TypeScript. **백엔드 없이 단독으로 동작합니다.**

```bash
npm install
npm run dev      # http://localhost:5173
```

기본값은 목 데이터(`VITE_API=mock`)라 브라우저 메모리에서 돕니다. 키워드를 등록하면
목록·필터에 즉시 반영되고, 새로고침하면 초기 상태로 돌아갑니다.

## 백엔드 붙이기

```bash
cp .env.example .env
# VITE_API=http
# VITE_API_TARGET=http://localhost:8000
npm run dev
```

호출 경로와 응답 형태는 [`docs/API.md`](../docs/API.md)에 있습니다.
가장 작은 범위는 `GET /keywords` + `POST /keywords` 둘뿐입니다.

부분 전환(키워드만 실제 API, 나머지는 목)은 `src/api/index.ts`에서 두 구현을
메서드 단위로 섞으면 됩니다.

## 구조

```
src/
├─ api/            ← 백엔드와의 유일한 접점
│  ├─ types.ts        도메인 타입 (정본)
│  ├─ contract.ts     UI 가 기대하는 인터페이스
│  ├─ mock.ts         브라우저 메모리 구현
│  ├─ http.ts         REST 구현
│  └─ index.ts        VITE_API 로 둘 중 하나 선택
├─ components/     TopBar · Screen · 공용 UI(칩·버튼·미터·길이트랙)
├─ screens/        Dashboard · Lectures · Keywords · Runs
├─ hooks/          useAsync (로딩·오류·재시도·경쟁조건 처리)
├─ lib/format.ts   시간·토큰·날짜 포맷
└─ styles/         tokens.css (디자인 토큰) + global.css
```

**화면 코드는 `api` 하나만 import 합니다.** 어느 구현이 붙었는지 모릅니다.

## 설계 근거

목업 단계에서 확정한 것들이라 바꾸기 전에 이유를 확인하세요.
자세한 내용은 [`docs/mockups/ui.html`](../docs/mockups/ui.html) 각 화면 하단의 "설계 의도".

- **상단 메뉴 + 스크롤 자동 숨김** — 강의 화면이 이미 목록+읽기 2단이라 좌측 레일까지
  두면 세로 기둥이 셋이 됩니다. 폭이 아쉬운 읽기 영역에 그 218px을 돌렸고, 상단바가
  세로를 영구 점유하지 않도록 스크롤 시 접힙니다.
- **한 겹의 레이어, 하나의 시작선** — 상단바·제목·필터·본문이 모두 `--page-max`
  (1360px) 안에 들어오고 같은 왼쪽 선에서 시작합니다. 본문을 자기 칸 안에서 가운데
  정렬하면 단 사이에 빈 구멍이 생기고 본문만 떠 보여서, 칸을 그대로 채웁니다.
- **목록과 읽기가 한 화면** — 아카이브는 훑으면서 읽는 물건이라 화면을 오가면
  "어디까지 봤더라"를 매번 다시 찾게 됩니다. 목록 패널은 스크롤을 따라옵니다.
- **목록은 제목만** — 점수·채널·길이는 읽는 동안 쓰이지 않습니다. 전체 정보는
  마우스를 올리면(`title`) 나오고, 목록·챕터 패널은 각각 접어서 본문을 넓힐 수
  있습니다(선택은 브라우저에 기억).
- **이어보기** — 한 편의 끝에 다다르면 다음 편이 아래에 이어 붙고, 스크롤 위치를 따라
  주소와 목록 강조가 옮겨 갑니다. 뒤로 가기 기록은 남기지 않습니다(`replace`).
- **챕터 타임라인** — 막대 높이가 실제 챕터 길이 비율. 목록이 아니라 축척입니다.
- **타임스탬프는 전부 클릭 가능** — 요약본의 가치는 "다 읽게 하는 것"이 아니라
  "필요한 3분으로 보내주는 것"입니다.
- **키워드 필터를 전부 펼침** — 선택된 것만 칩으로 띄우면 선택지가 안 보입니다.
  0편인 키워드도 숨기지 않습니다(쿼터만 쓰고 성과가 없다는 신호).
