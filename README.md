# 덕!곳간 (duk-gotgan)

키워드를 걸어 두면 **유튜브에서 강의를 찾아 AI 가 요약해 쌓아 주는** 개인용 아카이브.

> 유튜브를 뒤지는 시간을 없애고, 읽을 수 있는 강의 노트만 남깁니다.

집 안의 맥 한 대에서 돕니다. 폰이든 노트북이든 같은 공유기에 붙어 있으면
`http://192.168.x.x:8000` 으로 들어가 읽습니다.

**소개 페이지 → https://seunggyun.github.io/duk-gotgan/**

---

## 어떻게 도는가

**세 가지 일을 따로 돌립니다.** 한 사이클이 검색부터 요약까지 다 하던
때는 앞이 막히면 뒤가 통째로 밀렸습니다 — 긴 영상 하나를 받아쓰는 동안
요약이 몇 시간씩 놀았습니다.

```
                    ┌─ 검색   1분마다 ─┐  유튜브에서 후보를 찾고 룰로 거릅니다
  키워드 등록 ────> │                  │
                    ├─ 자막  30초마다 ─┤  자막을 받거나, 막히면 소리를 받아씁니다
                    │                  │
                    └─ 요약   1분마다 ─┘  5편 모이거나 1시간 지나면 AI 를 부릅니다
                              │
                              └─────────> 곳간 (읽는 화면)
```

각 잡이 **끝낼 때 다음 상태를 세워 둡니다.** 서로를 기다리지 않고, 하나가
죽어도 나머지는 그대로 돕니다.

```
DISCOVERED ──> TRANSCRIPT_PENDING ──> TRANSCRIBED ──> PUBLISHED
     │                 │                    │
     │                 ├─ TRANSCRIBING      ├─ REVIEWING       (붙들고 있는 중)
     │                 └─ FAILED_TRANSCRIPT └─ FAILED_REVIEW
     └─ REJECTED_RULE
```

**AI 호출은 영상 한 편당 한 번입니다.** 자막을 읽고 요약을 만들어
정해진 형식으로 넘기는 것으로 끝납니다. 받아서 검증하고 담는 코드는 워커
프로세스 안에 있어서, AI 는 스키마에 맞는 값을 넘길 뿐 셸도 DB 도
만지지 않습니다.

**요약은 두 회사가 나눠서 합니다.** 구독 한 곳의 사용량으로는 줄이 줄지
않아서(대기 286편), 클로드 워커와 안티그래비티 워커를 따로 띄워 같은
줄에서 한 편씩 가져갑니다. 무엇을 쓸지는 `REVIEW_PROVIDER` 가 정하고,
락도 토큰 장부도 그 값으로 갈립니다.

```
요약 대기 ──┬─> 클로드 워커      (claude-opus-5)
            └─> 안티그래비티 워커 (gemini-3.1-pro-high, agy CLI)
```

**같은 영상을 둘이 요약하지 않습니다.** 조건부 UPDATE 로 한 건씩 집어서,
경합이 나면 진 쪽이 조용히 다음 후보로 넘어갑니다. 붙든 사람의 이름이
`videos.claimed_by` 에 남아 있어, 남이 도는 중인 것을 회수하지도 않습니다.

**한 번 처리한 영상은 다시 처리하지 않습니다.** `videos` 의 기본키가
유튜브 영상 ID 라, 두 키워드가 같은 영상을 데려와도 자막도 요약도
한 번입니다.

### 자막은 대개 직접 받아씁니다

유튜브 자막 API 가 이 집 IP 에서 막혀 있습니다(429). 그래서 소리를 받아
**맥의 GPU 로 직접 받아씁니다** — `mlx-whisper` 의 large-v3-turbo, M4 실측
5~6배속입니다. 자막 경로가 열려 있으면 그쪽을 먼저 씁니다.

### 비용

토큰은 **5시간 창** 단위로 셉니다(구독 사용량이 그 주기로 풀립니다).
유튜브 쿼터는 하루 단위라 장부를 갈라 뒀습니다.

```
요약 한 편   약 80,000 토큰   (7일 실측)
5시간 상한   3,000,000 토큰   → 창당 37편 · 하루 178편
지금 처리량  하루 36.6편      → 약 5배 여유
```

## 화면

**여러 사람이 씁니다.** 들어오면 누구인지 고르고, 비밀번호를 건 사람만
네 자리를 묻습니다. 고른 결과가 쿠키에 남아 다음부터는 바로 들어갑니다.

| 화면 | 하는 일 | 누가 |
|---|---|---|
| **덕질** | 요약을 읽습니다. 안 읽은 것이 먼저, 그다음 유튜브 최신순 | 모두 |
| **키워드** | 무엇을 모을지. 남이 등록한 것을 구독할 수도 있습니다 | 모두 |
| **제외함** | 뺀 것. 되돌리거나 완전삭제(주인만) | 모두 |
| **대시보드** | 오늘 얼마나 모았나, 토큰·쿼터를 얼마나 썼나 | 주인 |
| **대기 목록** | 줄 서 있는 영상. 처리 전에 뺄 수 있습니다 | 주인 |
| **실행 로그** | 지금 어디까지 왔는지, 무엇을 했는지 | 주인 |

**보이는 범위는 사람마다 다릅니다.** 요약 본문은 모두가 같은 것을 보지만,
어떤 강의가 목록에 오르는지는 그 사람이 구독한 키워드가 정하고, 읽음·
즐겨찾기·제외는 각자 따로 쌓입니다.

**수집은 나누지 않습니다.** 그래서 사람이 늘어도 비용이 늘지 않습니다 —
비용은 사람 수가 아니라 **서로 다른 키워드 수**에 비례합니다.

## 구성

한 대에서 세 프로세스가 돕니다. `launchd` 가 로그인할 때 알아서 띄웁니다.

| | 하는 일 | 스택 |
|---|---|---|
| **api** | 화면과 REST 를 **한 포트(8000)** 에서 | FastAPI · SQLAlchemy 2 · Python 3.12 |
| **worker** | 검색·자막·요약·정리 네 개의 루프 | asyncio (`backend/scripts/worker.py`) |
| **mysql** | 저장 + 한국어 전문 검색 | MySQL 8 (ngram FULLTEXT) · 도커 |

화면은 React 19 + Vite + TypeScript 이고, 빌드 결과를 api 가 그대로 냅니다.

**큐도 브로커도 없습니다.** 잡 사이의 배타 제어는 MySQL 의 `GET_LOCK` 으로
합니다. 프로세스가 한 대에 셋뿐이라 Redis 를 하나 더 띄울 이유가 없습니다.

**AI 는 API 키가 아니라 구독을 씁니다.** 이 맥에 로그인된 Claude Code 를
`claude-agent-sdk` 로 헤드리스 실행합니다.

지금 규모 — 영상 1,498건 · 요약 339편 · DB 55MB.

## 개발

```bash
# 백엔드
cd backend
uv sync --extra dev --extra asr
.venv/bin/uvicorn app.api.main:app --reload --port 8000
.venv/bin/python -m pytest          # 113건

# 화면 (개발 서버 5173, /api 를 8000 으로 프록시)
cd frontend
npm install
npm run dev
```

`frontend/.env` 의 `VITE_API=mock` 으로 두면 **백엔드 없이** 화면 전체가
브라우저 메모리에서 돕니다.

## 원칙

1. **자막은 믿지 않습니다.** 남이 쓴 텍스트를 도구 가진 에이전트에 넣는
   구조입니다. 도구는 `Read`(작업 폴더 안)와 `save_review`(인프로세스)
   둘뿐이고, 셸·파일 쓰기·네트워크는 어떤 경우에도 열지 않습니다.
2. **AI 에게 능력이 아니라 인터페이스를 줍니다.** 저장이 필요하면 범용
   셸이 아니라 타입 있는 도구 하나를 주고, 구현체는 샌드박스 밖에 둡니다.
3. **싼 필터를 먼저.** 룰로 거른 뒤에 AI 를 부릅니다.
4. **사용자가 보는 것은 `lectures` 뿐입니다.** 탈락분은 조인 대상이 아니라,
   조건을 빠뜨려 노출되는 실수를 구조로 막습니다.
5. **모든 단계는 다시 할 수 있습니다.** 영상 단위 상태로 어디서 실패해도
   그 지점부터 재개합니다.
6. **원저작자 우선.** 요약에는 항상 원본 링크·채널·타임스탬프를 붙이고,
   자막 원문은 처리용으로만 30일 보관합니다.
