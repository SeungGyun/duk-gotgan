챕터

막대 높이 = 챕터 길이 비율

중복 결제는 한 곳을 막아서 해결되지 않는다. 클라이언트·게이트웨이·DB·정산 네 지점에 각각 다른 성격의 방어를 두어야 한다.

강연자는 실제 운영 중 발생한 이중 청구 사고를 재구성하며 시작한다. 네트워크 타임아웃 후 클라이언트가 재시도했고, 게이트웨이는 두 요청을 서로 다른 것으로 보았으며, DB 유니크 제약은 두 트랜잭션이 커밋되기 전 구간에서 무력했다. 이 사고를 축으로 방어 계층을 하나씩 쌓아 올리고, 각 층이 막는 실패와 막지 못하는 실패를 분리해 설명한다. 마지막에는 이미 운영 중인 시스템에 어떤 순서로 도입해야 위험이 적은지를 다룬다.
